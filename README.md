# Gunsmoke Arcana

西部劇のガンマン × 荒野 × ファンタジーの、スマホ縦持ち向けカード対戦ゲーム。

### ▶ あそぶ

**https://nakanaka0318.github.io/gun-card-/**

スマホのブラウザでそのまま開けます。インストール不要。

---

## これは何か

単一ファイルのHTML（約1.0MB / 約14,000行）。ビルドもサーバーも要りません。
`index.html` をブラウザで開けばそれだけで動きます。

| 項目 | 現在値 |
| --- | --- |
| カード種類 | 547 |
| バージョン | ver1 〜 ver9 |
| フォーマットデッキ | 45（ver1〜ver9 × 5クラス） |
| クラス | フォーメーション / アクセル / ドミニオン / アルカナ / マキナ（＋エニグマ＝ニュートラル） |

主な仕組み: PP・進化(EP)・超進化(SEP)・バッジ・融合（手札で行う）・奥義・成長・
状態（温存／強気／全力）。

## 音楽

画面ごとに曲が変わります。音源ファイルは持たず、効果音と同じくその場で合成して鳴らすので、
単一ファイルのままです（ブラウザが音を出せるようになる仕様上、最初に画面を一度触ってから鳴り始めます）。

| 画面 | 曲 |
| --- | --- |
| ホーム | 荒野の夕暮れ |
| 設営・2PICK・フォーマット・みんなのデッキ | 出立の支度 |
| デッキ編成・カード一覧 | 卓上の工房 |
| ルールブック | 夜の読書 |
| 相性検証 | 検証の刻み |
| 決闘 | 対峙 |
| 決着のあと | 決着の余韻 |

音楽と効果音は別々に切り替えられます（ホーム下部のボタン、決闘中は設定から）。
曲を足したり直したりするときは `BGM_TRACKS` に書き足してください。1小節＝16ステップで、
`chords` が小節ごとの和音（MIDI番号）、`voices` が各パートの鳴る位置と音色です。

ver9 は6クラスそろって各8枚（＋トークン2枚）。クラスごとに軸が違う。

| クラス | 軸 |
| --- | --- |
| エニグマ | 山札で捨てられた時に働く／融合 |
| フォーメーション | 山札を削る。残り枚数が条件。山札切れを勝利に変えるバッジ「空絶の顕現」 |
| アクセル | アミュレットとPP最大値 |
| ドミニオン | 「財布」の購入値を融合で貯め、品物と引き替える |
| アルカナ | そのターン自分のフォロワーが1体も攻撃していないと働くバッジ |
| マキナ | **共鳴**＝自分の山札が偶数のときに追加効果。引く／捨てるで偶数奇数を操る |

モード: 対CPU戦、2人対戦、EvE（検証用）、2PICK、フォーマットデッキ、デッキ編成、相性検証、戦績、調整履歴、カード一覧、ルールブック。

## 操作

指で遊ぶ前提の画面です。つまんでの拡大、二度叩きの拡大、長押しの文字選択とコピー吹き出しは
どれも止めてあります（入力欄とデッキ文の書き出しだけは選んでコピーできます）。
対戦は縦持ち・横持ちのどちらでも遊べます。横持ちでは相手の手札の裏を省いて縦の余白を空け、
そのぶん札を大きくして、盤面を画面の中央にまとめます。

札を並べて選ぶ場面（マリガン、融合、2PICK）では、札の絵は小さくて効果の文が読めないので、
絵の下に文そのものを並べています。引き直す札や、融合の素材にできない札は、文の側にも印が付きます。

### デッキ編成

一度に見える枚数を増やすため、操作するものは上の2段にまとめ、残りを全部札に充てています
（スマホ縦画面で画面の高さの17%ほど。開いた時点で札が30枚見えます）。

見出しの帯＝**デッキ名・クラス**／**◯◯/40**（押すと**デッキ確認**）／**設定**。
その下の帯＝**コストの分布**（棒を押すとそのコストだけに絞れる。もう一度押すと解除、複数選べる）と、
**カード名・効果で探す**欄。どちらも巻いても画面に残ります。

デッキ確認では、今入っている40枚をコスト順にまとめて、フォロワー／スペル／アミュレットの内訳と一緒に見られます。

表示は2つあります。

- **並べる** — 開いた瞬間から札が並びます。**押すと1枚入り**、**右上の数字を押すと1枚減り**、
  **長く押すと効果の画面**が開きます。減らすボタンを札の下に置いていないので、
  入っている札も入っていない札も同じ高さで並びます。
  押しながら指を滑らせた時（巻いている時）は効果の画面を開きません。
- **効果を読む** — 札・種別・コスト・攻防・キーワードに加えて**効果の全文**が出ます。
  読みながらその場で ＋ − で足し引きできます。札を押すと、関連カードまで載った詳しい説明が開きます。

並ぶ列の数は画面の幅に合わせて変わります（スマホ縦5列、横画面やタブレットでは11〜14列）。
横画面では分布と探す欄が横に並んで1段になり、盤面に高さを譲ります。

デッキ名・クラス・絞り込み・保存済みデッキは「設定」を押すと開きます。
「デッキの中だけ」で、今入っている札だけに絞れます（このときは見出しで区切らず詰めて並べます）。

### 調整履歴（UPDATES）

カードとルールを直した記録です。新しいものが上に並び、**カード名を押すとそのカードの説明が開きます**。

- 「決まりごと」「下方修正」「上方修正」「そのほか」に分かれます
- カードの変更は **変更前 → 変更後** の形で出ます
- 理由を書いたものは、その下に添えて出ます

中身は `index.html` の `UPDATES` 配列です。新しい回は配列の**先頭**に足してください。

```js
{ date: '2026-11-20', title: '◯◯の調整', note: '狙い',
  groups: [{ head: '下方修正', items: [
    { kind: 'card', id: 'goblin_001', name: 'ゴブリン', from: '1/2', to: '1/1', why: '理由' }
  ]}] }
```

`kind` は `card`（カード）／`rule`（決まりごと）／`new`（追加・改名）。
`id` を書くとそのカードの説明へ飛べるようになり、テストが
「IDが実在するか」「名前が今のカード名と一致するか」を毎回確かめます。

### 登場演出（ENTRY FX）

**47枚**のカードには、場に出る前に流れる**専用の演出**が付いています（**43種**）。

- 演出が**終わってから**カードが場に出ます。スペルは**効果が働く前**に流れます
- 手札から出しても、効果で出てきても、山札から出てきても同じ演出が流れます
- **同じ札を1.8秒以内に続けて出した**ときは、2枚目以降の演出を省いてテンポを保ちます
- 端末が「動きを抑える」設定のときは流しません。自動対戦（`G.sim`）でも作りません
- ホームの **ENTRY FX** から一覧を開けます。枠を押すとその演出だけが流れ、「続けて再生」で全部を順に見られます

中身は `index.html` の三つです。

| 名前 | 役割 |
| --- | --- |
| `EFX_PARTS` | 画面を使う小さな部品（幕・光柱・輪・破片・花弁・歯車…37種）。DOMを置くだけで、動きはCSSの `@keyframes` が持つ |
| `ENTRY_FX` | 札ごとの演出。名札・色三つ（`ck`／`ck2`／`bg`）・長さ `ms`・揺れ `shake`・音 `sfx`・部品の並び `parts` |
| `ENTRY_FX_OF` | カードID → 演出名の割り当て。**カードの定義（`CARDS`）は触りません** |

```js
/* 演出をひとつ足す */
mypattern: {
  name: '焔環', kana: 'RING OF FIRE',
  ck: 'rgba(222,86,40,.58)', ck2: 'rgba(255,224,170,.95)', bg: 'rgba(18,4,2,.86)',
  ms: 1200, shake: 1, sfx: 'rumble',
  parts: [['veil', { d: 1200 }], ['ring', { n: 3, gap: 130 }], ['flame', { n: 3, d: 1000 }]]
}
/* 札に割り当てる */
ENTRY_FX_OF.mycard_001 = 'mypattern';
```

部品の指定に `ck` / `ck2` を書くと、**その部品だけ色を変えられます**（双極の炎と水がこれです）。
演出そのものは `FX.entry(cardId, destSel)`、一覧からの見本は `FX.playEntry(key, cardId, dest, shakeSel)` が流します。
どの演出にも、自動で**下地（`.e-scrim`）**と**名札（`.e-name`）**が付きます。

### EvE（検証用）

準備画面の **EvE** から始めると、**両方をAIが操作**します。

- **1ターンごとに3秒止まる**ので、人間が目で追えます
- **どちらの手札も表向き**で見えます（横画面でも相手の手札を出します）
- 引き直しは飛ばし、ターンタイマーは切れます
- 盤面は裏返らず、上がAI 2・下がAI 1で固定です
- ホームなどに移ると自動進行は止まります

AIの打ち方は「AI検証」の勝率を出しているものと同じなので、**その数字がどういう試合から出ているのかをそのまま見られます**。

### 決闘の準備

プレイヤー1・2それぞれのデッキの横に「**ランダム**」があります。保存済みデッキから選び直します
（40枚そろったデッキだけが候補。押すたびに変わるよう、今選んでいるデッキは候補から外します）。

### 戦績（自分がやった試合から相性表をつくる）

自分が実際に遊んだ試合をためて、**自分だけの相性表**を作ります。

決着の画面の「**戦績に残す**」を押すと、自分と相手のクラス・デッキ名・先攻後攻・勝敗・ターン数がそのまま1件入ります
（同じ試合を二度押しても増えません）。手で入れることもできます。

たまった記録から出るもの:

- **通算／先攻のとき／後攻のとき**の勝率
- **相性表**。マスは勝率と「勝-敗-分」。不利は錆色、五分は灰色、有利は緑
- **クラスで見る**（縦が自分のクラス、横が相手のクラス）と
  **デッキ同士で見る**（縦も横もデッキ名）の切り替え。
  デッキ同士では、逆向きに記録した試合も裏返して数えるので、
  **相手に使ったデッキも行に出ます**。
  1人回しで ver1フォーメーション が ver2フォーメーション に勝った場合、
  ver1の行に 1-0、ver2の行に 0-1 が両方出ます
- 新しい順の記録一覧（1件ずつ消せる）、戦績のテキストコピー、全消し

記録はこの端末（ブラウザ）に保存されます。別の端末には移りません。

#### AI検証タブ

同じページの「**AI検証**」に切り替えると、フォーマットデッキ55種を
**このゲームと同じAI同士で総当たりさせた結果**が、実戦と同じ形の相性表で出ます。

- 1組100戦・**計148,500試合**。結果は `index.html` に焼き込んであり、遊ぶたびに計算し直しません
- **この表は 2026-11-02 時点で確定です。** 以降にフォーマットデッキが増えても、カードの効果やルールが
  変わっても取り直しません（その時点の記録として残します）
- 勝率順のランキング（S/A/B/C/D/E のティア付き）。デッキを押すと、そのデッキの相手ごとの相性が開きます
- バージョンで絞れます（ver9を選べばver9の5デッキだけの5×5）

#### verAI（AIが組んだ最強構築）

バージョンをまたいでカードを選び、**上のAI同士で1デッキあたり2,700試合ずつ**当てて確かめた5デッキです。
どのクラスでも、そのクラスの既存フォーマットデッキの最良を上回ります。

| クラス | verAI | 既存の最良 | 差 |
|---|---|---|---|
| アルカナ | 【verAI】要塞アルカナ **86.0%** | 守護アルカナ 80.3% | +5.7 |
| アクセル | 【verAI】断頭アクセル **71.9%** | ディスカアクセル 66.0% | +5.9 |
| マキナ | 【verAI】掃討マキナ **73.2%** | 進化マキナ 72.7% | +0.5 |
| ドミニオン | 【verAI】堅守ドミニオン **67.8%** | 切り替えドミニオン 58.0% | +9.8 |
| フォーメーション | 【verAI】城塞フォーメーション 65.3% | 温存フォーメーション **67.5%** | &minus;2.2 |

> 城塞フォーメーションは、積んでいた激震のゴリアテ・モルフェイ・オルテニアが
> 3枚とも能力調整を受けたため、クラス最上位から落ちています。
> **フォーマットデッキは調整のたびに組み直さない方針**なので、そのままにしてあります。

共通している考え方は「**このAIは守護の壁を抜けない**」です。
中立の激震のゴリアテ（4コス5/6守護）・影の暗殺者（5コス2/8 必殺覇気威圧）・試練の庇護者（5コス5/5 守護緩衝）が
どのクラスでも使えるため、これを軸に全体ダメージと除去を足しています。
アクセルだけは壁型が失敗したので（61%）、サガツマツの直接召喚を核にして守りを足す形にしました。

> 人間が遊ぶときはAIの弱点が当てはまらないので、verAIが人間同士でも最強とは限りません。

#### verAI理論（人間が使う前提の最強候補）

同じ verAI の中に、**自動対戦で確かめていない**5デッキが入っています。
AIにできなくて人間にできること ―― 出す順番を組み立てる／切り札を抱えて待つ／
選択肢を正しく選ぶ／打点を数える ―― だけを拠り所に、机上で組んだものです。

| デッキ | 人間側の勝ち筋 | AI検証での順位 |
|---|---|---|
| リノセウスOTKアクセル | 0コストの札を並べてから豪風のリノセウスを撃つ。3枚で 3X+3 打点、X＝6で21 | **54位 / 14.6%** |
| 零コススペルアルカナ | スペルを吐いてペンタクル・聖杯・ルナリア・アラを0コストにして一斉に撃つ | 11位 / 68.9% |
| 共鳴マキナ | 山札の偶奇を毎ターン合わせて、ライオの全体破壊とウンケイを確実に通す | 12位 / 68.4% |
| 購入ドミニオン | 財布に何を溶かしていつ買うかを決める。購入値40で20/20の億り人 | 19位 / 57.8% |
| 連携フォーメーション | ギルダリアを先に置いてから盤面の知略で5体出し、その場で全部殴る | 25位 / 55.5% |

**AI検証の順位が低いことが、そのまま「AIにはこの勝ち筋が踏めない」という意味**になります。
いちばん分かりやすいのがリノセウスOTKで、順番を組み立てられないAIが回すと55デッキ中54位まで落ちます。

> こちらは実測していません。人間同士で回した結果は「実戦」タブに記録して、机上の読みと突き合わせてください。

AIは「PPを使い切る組み合わせを探して安い札から出す／倒しきれるなら顔を殴る／
相打ちにならない交換を選ぶ」までです。**何ターンもかけて組み立てるコンボは作れない**ので、
豪風のリノセウスのようなOTKデッキは実際より低く出ます。

このAIは **PvE（AIとの決闘）の相手にも使われます**。

> カードやフォーマットデッキを直したら、焼き込んだ結果も取り直してください。

## 遊び方のとっかかり

- リーダーの体力を 0 にすれば勝ち。デッキが尽きた状態でドローしても負け。
- デッキは40枚、同名は3枚まで。
- 最大PPはターン1の **1** から **1-2-3-4-5-6-7-8-8-9-9-10** と増え、ターン12で上限10に届く。
- **威圧と覇気は、相手のリーダーを攻撃した時点で失われる**。守りに使うか攻めに使うかのどちらかしか選べない。
  フォロワーを攻撃した場合は失われず、効果でもう一度付与されればまた働く。
  変えるときは `MAX_PP_BY_TURN` だけ直せば、ルールブックの表もホーム下の表記も追従する。
- はじめてなら、ホームの「フォーマットデッキ」から出来合いのデッキで始めるのが早いです。

## 触るときの決まりごと

- **1行目の `<meta charset="utf-8">` は動かさない。** 文字化けします。
- **タイプ（種族）は、カードの「タイプ」行に書かれていない限り付けない。** `token` も同じ。
  仕様書の `タイプ:エニグマ　ゴールド　アミュレット` は「クラス・レアリティ・カード種別」であって、
  種族ではありません。エニグマは `cls: 'neutral'` に対応します。

## 構造のあらまし

データ駆動です。`CARDS` 配列（→ `CARD_BY_ID`）がカードの定義で、効果は
`{hook, cond, once, type, params}` の形で持ち、`EFFECTS` レジストリ（`registerEffect`）が実体を持ちます。
発動タイミング（hook）の一覧は `ABILITY_TERMS` にあり、ゲーム内のルールブック画面にそのまま出ます。
つまりカードを足す作業は、ほとんどの場合データを足すだけで済みます。

## 検証

`tests/` に Playwright の検証一式があります。

```sh
sh tests/run.sh
```

内訳は、カードのデータ整合性・用語集の網羅（t9）、新しい仕組みの挙動（t9b）、
各カードの挙動（t9c）、画面表示と自動対戦（t9d）、スマホ実機での表示と操作性（t9e）、
調整履歴とカードを出したときのずれ（t9m）、登場演出と一覧ページ（t9n）。

検証を書き足すときは、Google Fonts へのリクエストを必ず中断してください
（`page.route('**/*fonts.g*.com/**', r => r.abort())`）。中断しないと読み込みが詰まります。
